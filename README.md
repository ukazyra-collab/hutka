# Hutka — как выложить на свой хостинг

Папка содержит всё, что нужно, чтобы Hutka жила на своём адресе и была видна всем без логина:

| Файл | Что это |
|---|---|
| `index.html` | весь сайт одним файлом (треки, лаборатория, профили, админка) |
| `geo.txt` | карта мира для страницы треков |
| `supabase.js` | клиентская библиотека Supabase (v2.117.3), лежит рядом, чтобы не зависеть от CDN |
| `config.js` | **единственный файл, который надо заполнить** — адрес и публичный ключ Supabase |
| `supabase/schema.sql` | таблицы и права доступа (кто что может читать и писать) |
| `supabase/seed.sql` | 8 трасс ОАЭ с реальными данными и их конфигурации |
| `supabase/setup.sql` | schema + админ + seed одним файлом (для нового проекта) |
| `supabase/social.sql` | лайки, комментарии, подписки — запустить один раз после setup.sql |
| `supabase/ai.sql` | чаты, сообщения, кредиты — запустить один раз для AI-тренера |
| `supabase/community.sql` | v23: трассы от гонщиков (кто загрузил — тот и правит), классы картов, «полезно / не полезно» — запустить один раз после update.sql |
| `supabase/update.sql` | **всё вместе** (social + ai + поля профиля + community) — безопасно запускать повторно; достаточно одного этого файла |
| `supabase/functions/*` | серверные функции: тренер, кошелёк, Stripe |
| `manifest.webmanifest`, `sw.js`, `icon-*.png` | PWA: установка на телефон, «Поделиться → Hutka» из приложения Alfano (Android) |
| `supabase/functions/ask/index.ts` | серверная функция «Спросить ИИ» (ключ Anthropic хранится только на сервере) |

Схема: статический сайт (Netlify / Cloudflare Pages) + база и логин в Supabase + ИИ через функцию Supabase.
Бесплатных тарифов хватает на старт; карта понадобится только для домена и для API Anthropic.

Время на всё: ~30–40 минут.

## 1. База данных и логин — Supabase (бесплатно)

1. Зарегистрируйся на https://supabase.com → **New project**. Регион: *Asia Pacific (Mumbai)* или *Europe (Frankfurt)* — ближе всего к Дубаю. Пароль базы сохрани, но дальше он не понадобится.
2. Слева **SQL Editor** → **New query** → вставь содержимое `supabase/schema.sql` → **Run**. Должно быть «Success. No rows returned».
3. Там же новый запрос — добавь себя в админы (почта та, с которой будешь входить на сайт):
   ```sql
   insert into admin_emails (email) values ('u.kazyra@kozyramedia.com');
   ```
   Можно добавить несколько строк — все они получат админку.
4. Новый запрос → вставь `supabase/seed.sql` → **Run**. Появятся 8 трасс ОАЭ (Dubai Kartdrome со Standard/Extended/Reverse, Sharjah с четырьмя конфигурациями, Yas, Al Forsan, RAK, Karting Town, Indoor Kartdrome, Chaos Karts). Всё потом редактируется в админке сайта.
5. **Project Settings → API** (или **API Keys**): скопируй **Project URL** и ключ **anon public** (в новых проектах он называется *publishable key* и начинается с `sb_publishable_`). Это публичный ключ, его можно класть в `config.js` — все права ограничены политиками из `schema.sql`.

### Вход по ссылке на почту

Supabase по умолчанию отправляет письма **сам, но только 2 письма в час** — для публичного сайта этого мало. Два варианта (можно оба):

**А. Вход через Google (рекомендую, писем вообще не нужно)**
1. https://console.cloud.google.com → создай проект → **APIs & Services → OAuth consent screen** (External, название Hutka) → **Credentials → Create credentials → OAuth client ID → Web application**.
2. В *Authorized redirect URIs* добавь `https://<твой-ref>.supabase.co/auth/v1/callback` (точный адрес показан в Supabase: **Authentication → Providers → Google**).
3. Скопируй Client ID и Client secret в Supabase (**Authentication → Providers → Google → Enable**).
4. В `config.js` поставь `googleAuth: true` — в окне входа появится кнопка Google.

**Б. Свой SMTP для писем (магическая ссылка на почту)**
1. Заведи бесплатный аккаунт у почтового провайдера, например https://resend.com (3000 писем в месяц, нужен свой домен) или https://www.brevo.com (300 писем в день).
2. Supabase → **Project Settings → Authentication → SMTP Settings → Enable Custom SMTP** → впиши хост/порт/логин/пароль от провайдера и адрес отправителя (например `login@hutka.app`).

В любом случае зайди в **Authentication → URL Configuration** и поставь **Site URL** = адрес сайта (например `https://hutka.netlify.app`), и добавь его же в **Redirect URLs**. Без этого ссылка из письма ведёт на localhost.

## 2. AI-тренер: бесплатная бета, потом кредиты и Stripe

Пока функции не задеплоены, вкладка **AI coach** и панель «Спросить тренера» показывают «скоро» — ничего не ломается.

**Бесплатная бета (по умолчанию).** Функция `ask` работает в режиме `FREE_MODE=1`: никто не платит, кредиты не списываются, Stripe не нужен. Защита от выжигания токенов — лимиты честного использования (секреты, все необязательны):

| Секрет | По умолчанию | Что ограничивает |
|---|---|---|
| `LIMIT_HOUR` | 15 | вопросов в час на гонщика |
| `LIMIT_DAY` | 50 | вопросов в сутки на гонщика |
| `LIMIT_IP_DAY` | 120 | вопросов в сутки с одного адреса сети (от «сотни аккаунтов с одного компьютера») |
| `LIMIT_GLOBAL_DAY` | 800 | вопросов в сутки на всех — потолок расхода (~$25–40 в худший день) |
| `MAX_OUT_TOKENS` | 1200 | длина ответа |
| `AI_PAUSED` | 0 | `1` — выключить тренера мгновенно, без передеплоя |
| `FREE_MODE` | 1 | `0` — включить кредиты и Pro (Stripe, п. 2.4–2.6) |

Вопросы задают только вошедшие (ссылка на почту / Google), так что бот без аккаунта ничего не потратит. Плюс поставь **Spend limit** в консоли Anthropic (Billing → Limits), например $50/мес — это жёсткий потолок на стороне Anthropic. Расход виден в **Admin Panel → AI coach · usage and cost** (нужен `community.sql`).

### 2.1. Таблицы
SQL Editor → вставить `supabase/ai.sql` → Run (чаты, сообщения, кошельки, журнал кредитов).

### 2.2. Ключ Anthropic
https://console.anthropic.com → **Billing** → пополнить (от $5) → **API Keys → Create key**. Один ответ тренера стоит ~2–5 центов.

### 2.3. Функции (5 штук)
Supabase → **Edge Functions → Deploy a new function → Via Editor**. Для каждой: имя из списка, вставить код файла, **Deploy**, затем в настройках функции **выключить «Verify JWT»** (функции сами проверяют, что человек вошёл).

| Имя функции | Файл | Что делает |
|---|---|---|
| `ask` | `supabase/functions/ask/index.ts` | ответ тренера, хранит чат и расход токенов; в бете бесплатно, с `FREE_MODE=0` списывает кредит |
| `wallet` | `supabase/functions/wallet/index.ts` | в бете — сколько вопросов осталось сегодня; с `FREE_MODE=0` — баланс и план |
| `stripe-checkout` | `supabase/functions/stripe-checkout/index.ts` | открывает оплату пакета/подписки |
| `stripe-webhook` | `supabase/functions/stripe-webhook/index.ts` | получает от Stripe факт оплаты и начисляет |
| `stripe-portal` | `supabase/functions/stripe-portal/index.ts` | страница управления подпиской |

Для беты достаточно двух: `ask` и `wallet`. Stripe-функции — когда включишь оплату.

Через терминал быстрее: `npm i -g supabase && supabase login && supabase link --project-ref <ref>` и в папке `hutka/`: `supabase functions deploy ask wallet --no-verify-jwt` (позже добавь `stripe-checkout stripe-webhook stripe-portal`).

### 2.4. Секреты
**Edge Functions → Secrets** (или `supabase secrets set KEY=value`):

| Секрет | Откуда |
|---|---|
| `ANTHROPIC_API_KEY` | п. 2.2 — **для беты нужен только он** |
| `SITE_URL` | адрес сайта: `https://hutka.ai/` (для Stripe) |
| `STRIPE_SECRET_KEY` | Stripe → Developers → API keys → Secret key (`sk_live_…`; для проверки можно `sk_test_…`) |
| `STRIPE_PRICE_PRO` | id цены подписки (`price_…`), см. 2.5 |
| `STRIPE_PRICE_PACK25`, `STRIPE_PRICE_PACK80` | id цен пакетов |
| `STRIPE_WEBHOOK_SECRET` | Stripe → Developers → Webhooks → добавить endpoint `https://<ref>.supabase.co/functions/v1/stripe-webhook`, события: `checkout.session.completed`, `invoice.paid`, `customer.subscription.updated`, `customer.subscription.deleted` → Signing secret (`whsec_…`) |
| `FREE_CREDITS` (необязательно) | стартовые кредиты, по умолчанию 10 |

### 2.5. Товары в Stripe
Stripe → **Product catalog → Add product**:
- **Hutka Pro** — recurring, $29 / month → скопировать `price_…` в `STRIPE_PRICE_PRO`;
- **Starter pack (25 credits)** — one-time, $9 → `STRIPE_PRICE_PACK25`;
- **Season pack (80 credits)** — one-time, $24 → `STRIPE_PRICE_PACK80`.
Суммы можно менять; в `config.js` поле `pricing` — только надписи в окне покупки, поправь их в тон.

### 2.6. Проверка
Открой сайт → **AI coach** → в бете показывает «Free beta · 0/50 вопросов сегодня» → задай вопрос. С `FREE_MODE=0` показывает 10 кредитов. **Get credits → Choose** должен уводить на страницу оплаты Stripe и после оплаты возвращать на сайт с начислением (обычно 2–5 секунд).

## 2-old. ИИ-чат в лаборатории — функция `ask` (старое описание)

Без неё всё работает, просто панели «Спросить ИИ» не будет.

1. https://console.anthropic.com → **Billing** → пополни баланс картой (минимум $5; один вопрос ИИ по сессии стоит несколько центов) → **API Keys → Create key** → скопируй ключ.
2. Supabase → **Edge Functions → Deploy a new function → Via Editor** → имя `ask` → вставь содержимое `supabase/functions/ask/index.ts` → **Deploy**.
3. В настройках функции **выключи «Verify JWT»** — функция сама проверяет, что человек вошёл на сайт (иначе новые проекты Supabase с новыми ключами подписи могут отбивать запросы).
4. **Edge Functions → Secrets** → добавь `ANTHROPIC_API_KEY` = ключ из п.1. (По желанию `ANTHROPIC_MODEL`, по умолчанию `claude-sonnet-5-5`.)
5. Адрес функции: `https://<твой-ref>.supabase.co/functions/v1/ask` — его в `config.js`.

Ключ Anthropic **никогда** не кладётся в `config.js` — только в Secrets. Функция отвечает только вошедшим пользователям, так что чужие не смогут тратить баланс.

Альтернатива через терминал: `npm i -g supabase && supabase login && supabase link --project-ref <ref> && supabase functions deploy ask --no-verify-jwt && supabase secrets set ANTHROPIC_API_KEY=sk-ant-...`

## 5. Первый вход и проверка

1. Открой сайт → **Sign in** → войди своей почтой (той, что в `admin_emails`). В меню слева появится **Admin**.
2. Админка: проверь карточки трасс, загрузи логотипы и обложки, при необходимости поправь координаты (пин на карте) и часы работы. В редакторе конфигурации можно обвести трассу по аэрофото или задать эталонную сессию.
3. Лаборатория: загрузи `.alf2` → выбери трек и конфигурацию → сессия публикуется на страницу трека (галочка при загрузке). Другие увидят её в «Hot laps» и смогут сравнивать с собой.
4. Профиль: гоночное имя, страна, домашний трек, аватар — по нему тебя найдут через поиск.

### Трассы от гонщиков, классы картов, оценки (v23)
- Если GPS сессии не совпал ни с одной трассой, при загрузке можно **добавить новую**: название, город и страна подставляются автоматически, страница трассы и первый лейаут создаются вместе с сессией. Кто добавил — тот и правит (пункт **My tracks** в меню); админы правят всё, удаляют только админы.
- У каждой сессии есть **карт**: список картов трассы (прокатные) или спортивный карт (Rotax, X30, KZ…). Лаборатория сравнивает только внутри одного класса — спортивный и прокатный не смешиваются; в списке «Другая сессия…» их можно показать принудительно.
- Вместо лайков — **👍 полезно / 👎 не полезно**. Сессия, которую трое и больше отметили «не полезно» (и их больше, чем 👍), помечается и уходит в конец ленты и списков.
- Для всего этого нужно один раз запустить `supabase/community.sql` (или `update.sql`). Пока он не запущен, сайт работает как раньше: трассы добавляют только админы, оценки — обычные лайки.

### Спутниковый снимок под трассой (v24)
- В Lab, на странице конфигурации и в редакторе есть кнопка **Satellite**: под линией трассы рисуются снимки Esri World Imagery (бесплатно, с подписью «Imagery © Esri…»; ключ не нужен). GPS-линия ложится на снимок автоматически (система координат одна и та же).
- Если GPS и снимок разошлись на пару метров — в редакторе конфигурации (My tracks / Admin → лейаут) шаг **3. Satellite imagery → Align imagery**: перетащить картинку под линией или стрелками по 0,5 м → «Save corners». Сдвиг хранится в лейауте и применяется у всех.
- Другой провайдер снимков — в `config.js`: `satTiles: "https://…/{z}/{x}/{y}.png"`, `satAttribution: "…"`, `satMaxZoom: 20` (Mapbox/MapTiler с ключом, если понадобится более свежий снимок).

### Кокпит на телефоне (v25)
- Поверни телефон горизонтально в Lab (или нажми **Map** вертикально) — Lab становится кокпитом как в приложениях логгеров: карта и спутниковый снимок на весь экран, линия круга, **HUD** сверху (время круга, скорость / время / дистанция в точке, Δt к сравнению), круглые кнопки справа (спутник, сравнение, повороты, график, тренер, ещё), внизу **бегунок по кругу** — тяни его, цифры и маркер на карте едут вместе; слева от бегунка ‹ T3 › — шаг по поворотам, тап по номеру открывает разбор поворота.
- Карту на телефоне можно **крутить двумя пальцами** (как зум щипком, только поворот); ⌂ в «ещё» возвращает исходный вид.
- Повороты / дайджест / обсуждение / тренер и выбор сравнения открываются шторкой справа (вертикально — снизу). Ориентацию экрана не блокируем — только подсказка «поверни телефон» в вертикальном режиме.
- В `manifest.webmanifest` `orientation` теперь `any` — установленное на домашний экран приложение тоже поворачивается.
- При загрузке сайт снимает чужие service worker'ы и кэши (старый сайт на том же домене не будет показываться из кэша).

### Классы картов и раздельные рейтинги (v26)
- При загрузке сессии карт выбирается из списка: прокатные модели этой трассы (Sodi RT8, Birel N35… — список трассы) или спортивный класс по семействам: Rotax (Micro/Mini/Junior/Senior MAX, DD2), IAME (Mini Swift, X30 Junior/Senior/Master, KA100), OK/OKJ/OK-N, KZ/KZ2, Vortex ROK, 4-тактные (LO206, Honda cadet, Prokart) и т.д.; «Другой…» — своё название. Старые сессии с текстом вроде «Rotax», «X30 jr» распознаются в класс автоматически.
- **Рейтинги никогда не смешивают карты**: на странице трассы у Hot laps вкладки по картам (своя десятка на каждый), на странице конфигурации сессии сгруппированы по карту, гид по поворотам строится по самому массовому карту, личные рекорды гонщика — отдельно на каждом карте, в Lab сравнение предлагает только тот же карт (прокатный с неизвестной моделью считается совместимым с любым прокатным; остальных можно показать «всё равно»).

### Приложение для iPhone / Android (v25.2)
- Папка `app/` в репозитории — нативная оболочка (Capacitor) вокруг сайта: вход через системный браузер с возвратом по `hutka://auth`, «Открыть в Hutka» для `.alf2`, иконки, сплэш. Приложение показывает живой сайт, так что обновления сайта попадают в него без пересборки. Весь путь до App Store и Google Play по шагам — в `app/README.md`.
- Для магазина нужна страница политики — `privacy.html` на сайте (почта `hello@hutka.ai` в ней — заведи ящик или поменяй).
- В окне входа появились вход по паролю («У меня есть пароль» — для аккаунта ревьюеров Apple) и кнопка  Apple (`appleAuth: true` в `config.js` после настройки провайдера Apple в Supabase). Внутри приложения кнопка Google показывается только вместе с Apple — требование App Store.

### Превью ссылки (v29.4)
Когда ссылку на hutka.ai кидают в Telegram / WhatsApp / iMessage / соцсети, показывается карточка: логотип, «Hutka — racing AI for karting», описание и картинка (`og.png`, 1200×630). Теги Open Graph и Twitter card — в `<head>`. Telegram кэширует превью: если показывает старое — боту @WebpageBot отправить ссылку, он обновит. Картинка одна на весь сайт (страницы — хэш-роуты, их краулеры не видят).

### Импорт: второй, более мягкий взгляд на линии
Если по обычным правилам замкнутой трассы рядом с треком не нашлось (кольцо 300 м – 3,5 км, разрывы до 25 м), импорт смотрит ещё раз, мягче: ищет небольшие уличные трассы, нарисованные кольцом. Крытых треков это не касается.
- Кольцо засчитывается от 150 м, а не от 300.
- Трасса самой площадки, нарисованная незамкнутой линией (`leisure=track`, не замкнута), тоже идёт в дело (`path` у элемента). Концы соединяются, только если между ними не больше 25 м, как у raceway.
- Разрывы шире 25 м так и остаются разрывами. Пробовали соединять до 50 м, и на пробном прогоне по Германии прямые сшивали два края одной ленты асфальта или пит-лейн с трассой. Такие линии хуже, чем никакие.
- Учитывается только то, что лежит внутри контура площадки или не дальше 250 м от её точки.
- Кольцо должно быть не меньше 70 м в поперечнике, как и для детских аттракционов (`TINY_M`). Компактное кольцо 150–200 м в 45 м — размер аттракциона, такому треку линию не даём.
- Кольцо должно быть похоже на трассу: извилистое, от 10 точек (тот же тест, что для контуров, `trackLike`). Коробка заасфальтированной площадки, овал или парковка, нарисованные как raceway, не подходят. На пробе по Венгрии и России 9 из 29 найденных колец оказались такими коробками, тест отсеял все 9.
- Найденное кольцо должно быть основной частью того, что нарисовано рядом: всё нарисованное не длиннее двух длин кольца плюс 200 м. Маленькое кольцо рядом с большой трассой, нарисованной кусками, — не эта трасса. Лучше без линии, чем с чужой.
- Детские аттракционы (всё в пределах 70 м) по-прежнему не заходят.
- На такую линию тратится не больше 400 мс за область: у функции всего 2 с процессора.

Линия получает пометку `loose: true` (у линии раскладки и в media), так что её всегда можно найти. Пробный прогон (`dry` + `mode: "update"`) отдаёт `linesLoose` и `shapes`: формы таких линий в метрах от первой точки, по 48 точек. По ним проверяем, что это действительно трассы.

- **Не картинг**, как бы ни стояла метка на карте: трассы soap-box derby (гонки на самодельных безмоторных машинках с горки) и учебные площадки автошкол («Учебный автодром», «Автошкола», «Driving school», «Fahrschule») (`lib.ts` → `NOT_KARTING`).

### «No internet», когда интернет есть (v34.56)
- **Что было**: с v34.27 приложение верило браузеру. Если `navigator.onLine === false`, оно показывало «No internet» и не отправляло ни одного запроса к базе. Но на iPhone веб-вид (приложение, Safari, приложение с домашнего экрана) иногда говорит «offline» при рабочей сети, например после переключения Wi-Fi ↔ мобильные данные или с VPN. Тогда Хутка писала «No internet», хотя остальные сайты грузились, токен входа не обновлялся, и функции получали просроченный токен (в логах 22 окт 00:57–00:59: `auth/v1/user` 403 «token is expired», `wallet` 401).
- **Что теперь**: `NET` в `store.js`. Пока браузер говорит «offline», приложение само проверяет связь маленьким запросом к сайту (`version.txt?net=…`, мимо service worker): сразу, затем каждые 15 с и при возврате приложения на экран. Запрос прошёл — значит, связь есть, баннер убирается, списки загружаются, токен обновляется. Любой успешный запрос к базе тоже это подтверждает, а неудачный при «offline» от браузера снова включает офлайн. Все проверки `navigator.onLine` в приложении заменены на `NET.off()`.
- Без связи всё как раньше: старт на трассе без сигнала, чтение прибора, сессии сохраняются и потом загружаются.
- Тесты: `t117_falseoffline.js` (браузер «врёт» → онлайн; сеть реально пропала → баннер вернулся; сети нет → баннер стоит), `t95_offline_start.js` (в симуляции без сигнала проверочный запрос тоже не проходит), `t94_offline.js`.

### Прочитанный план сохраняется в конфигурации для всех (v34.54)

Чужой рисунок не перезаписывается, сессии и линии с карты не трогаются. Редакторы трассы сохраняют как обычно.

### План с номерами поворотов читается по номерам (v34.53)
- **Что было**: на плане Dubai Kartdrome «Reverse Links» все конфигурации нарисованы одинаково серым, есть мост и пит-лейн, а повороты подписаны T1–T22. Трассировщик (`AT.best`) брал из такой картинки не тот кусок дорог и отвечал «Could not read the layout from this picture».
- **Что теперь**: ИИ (`ask`, `identify_track`) кроме названия и конфигурации возвращает `turns`, то есть где на картинке стоит каждый номер поворота, по порядку (`{n, x, y}`, доли ширины и высоты). Приложение идёт по дорогам от номера к номеру (`AT.route`). Каждый номер привязывается к ближайшим дорогам, до четырёх вариантов. Из них выбирается самый короткий круг через все номера. Тупики «туда и обратно» отрезаются, а номер, оказавшийся в тупике, перепривязывается. Круг, который заметно короче ломаной через номера, не принимается: это значит, что часть круга пропущена.
- Номера могут стоять неточно. На этом плане круг тот же при ошибке до ~2,5 % картинки в каждую сторону, при сдвиге всех номеров на 30 px и при округлении до 5 %. При большой ошибке план честно не читается, неверный круг не показывается. Направление движения берётся из порядка номеров.
- Ответ ИИ читается, даже если JSON обёрнут словами или в нём лишняя запятая. В лог функции пишется короткая строка на каждый разбор: что вернулось, сколько номеров. Картинка в лог не пишется.
- Тест `t115_revlinks.js`: план Reverse Links → Reverse Links открывается, видны повороты и траектория. Если ИИ не прочитал номера, приложение прямо говорит, что план не прочитан.

### Трассы: длина и повороты вместо расстояния, прогноз сразу, больше линий (v34.44)
- **Список трасс** — без расстояния до гонщика: «Где катаются» (сессии) сверху, ниже трассы с линией — самые длинные первыми (длиннее — серьёзнее гонки: международные трассы 1–1,7 км, крытые 300–600 м; при равной длине — больше поворотов), потом остальные по алфавиту. В строке — город, **длина и число поворотов** («1384 м · 17 поворотов»), у крытых без линии — «крытая». Страна по умолчанию — своя (профиль, домашняя трасса или часовой пояс), пока гонщик сам не выберет другую или «Все» (выбор запоминается).
- **Страница конфигурации**: под названием — длина, повороты (как их нумерует карта), «по часовой» для линии с карты без одностороннего движения (так она и нарисована), сессии.
- **Потенциальный лайн сразу**: на конфигурации, где на Hutka ещё никто не ездил, но есть линия (с карты, рисунок, схема), «Гид по поворотам» сразу показывает **прогноз Hutka AI** — траекторию, торможение, сброс газа, газ и каждый поворот словами (из похожих поворотов трасс, где катаются). Номера поворотов — те же, что на карте сверху (остальные повороты карты прогноз проходит в газ). Первая опубликованная сессия делает гид настоящим.
- **Импорт — больше линий**: кроме нарисованных raceway линия берётся из самой трассы площадки, нарисованной замкнутым контуром (`leisure=track`: её середина или край асфальта), если форма похожа на трассу, а не на коробку площадки (компактность и выпуклость); raceway с концами в 25 м друг от друга сшиваются. У каждой линии — источник (`from`: raceway/joined/outline) и **число поворотов** (считается тем же кодом, что и на странице, `corners.ts`; тест `importtest/test_corners.mjs` сверяет с приложением).
- **Режим «update»** очереди (`import_queue.mode = 'update'`): новые площадки как обычно, а свои прежние трассы импорта (`osm-…`) получают то, что дают правила сейчас — линию, где её не было (только «Main», без своей линии, рисунка и сессий), число поворотов у имеющейся линии, другие названия с карты. Пробный прогон (`dry`) показывает, что будет добавлено.
- **Очередь пережидает простой базы карты**: если QLever отвечает 5xx или недоступен, область остаётся в очереди (`pending`, `result.down`), попытка не засчитывается, и очередь спрашивает снова через 5 минут — один запрос, а не вся очередь в ошибках за минуту. Площадка рядом с трассой, сделанной вручную (не `osm-…`), не добавляется ближе 1,5 км от неё (булавка ручной трассы может стоять у въезда).
- **Названия**: у трассы хранятся другие названия с карты (`aka`: местное, официальное, старое, бренд) — поиск находит и по ним; если на карте есть русское название (`name:ru`), в русском интерфейсе показывается оно. «The Republican sport and technical center DOSAAF» переименована в «Стайки (ДОСААФ)».
- **Поиск по карте вручную**: функция `tracks-import` с `{area:"BY", find:"Стайк|Staik"}` возвращает теги элементов области под этим названием, с `{ids:["way/832870199"]}` — теги и геометрию элементов.

### Трассы с карты: Европа и США из OpenStreetMap (v34.42–v34.43)
- **Импорт** — серверная функция `tracks-import`: для страны (`FR`) или штата США (`US-CA`) берёт с OpenStreetMap все места с `sport=karting` (или картингом среди других видов спорта) и названием, а также названные по-картинговому (Go Karts, Kartbahn, Kartódromo, Картодром, Motokáry, mikroautorata…) raceway, трассы, спорткомплексы и залы без вида спорта и мотоплощадки с `sport=motor` (через QLever — SPARQL-базу всей карты Университета Фрайбурга: серверы Overpass отказывают облачной сети функций; пять лёгких запросов на область — теги и контуры мест, линии и теги raceway, города) — город (из адреса, иначе ближайший город), адрес, сайт, телефон, крытая/открытая. Куски одной площадки (центр, его трасса, точка на карте) склеиваются в одну трассу. У каждой — конфигурация «Main».
- **Линия**: если трасса нарисована на карте (`highway=raceway`), её середина — линия «Main»: своя петля площадки 300 м – 3,5 км (не соседний автодром), направление — по `oneway`, иначе по часовой. Точки лежат в `media` (`tracks/<id>/layouts/main/media/line`), у конфигурации только `line: {src:'osm', n, lengthM, driven}` — каталог остаётся лёгким.
- **Без дублей**: id трасс — от элемента OSM (`osm-w123`); площадка в 300 м от трассы Hutka (или в 1 км с тем же названием) пропускается; повторный запуск ничего не удваивает.
- **Очередь**: таблица `import_queue` (страна/штат, статус, итог в `result`); cron `hutka-tracks-import` каждые 10 секунд вызывает `hutka_import_step()`, она отправляет следующую область в функцию через `pg_net` с токеном из Vault (токен не покидает базу; функция проверяет его `hutka_import_token_ok`). Админ может вызвать функцию и своим входом. Добавить страну: `insert into import_queue(area) values ('TR');` (и cron, если он снят). Область `PING` — проверка, отвечает ли база карты и как быстро. Детские и педальные карты (mini-auto, Mini-Kart, Kids, per bambini, pédale, verkeerspark…), закрытые по названию («Ex …», «abbandonato», «former»), монастыри Kartause, усадьбы kartano и прочие «kart» не про картинг пропускаются. Когда в очереди не остаётся работы, задача cron выключается сама (`active = false`, v34.44); поставив области в очередь, включить её: `select cron.alter_job((select jobid from cron.job where jobname = 'hutka-tracks-import'), active := true);`. Порядок — по `prio` (больше — раньше), потом по коду области. Пробный прогон (`dry`) перечисляет в `result.names` все новые площадки — так проверяется любое изменение правил до записи.
- **В приложении** линия с карты работает как линия по GPS (кадр Web Mercator): сессии к ней привязываются, загрузка находит по ней трассу и конфигурацию, под ней спутник, Hutka AI считает идеальный круг; первая опубликованная сессия заменяет её реальной. На странице трассы — «С карты · © OpenStreetMap» (лицензия ODbL), обложка из линии, в каталоге — «линия есть». Буквы трассы без логотипа — первые буквы первых двух слов, знаки пропускаются (Briggs & Stratton → BS).
- **Тысячи трасс**: трассы и конфигурации грузятся страницами по 1000 (лимит API); в «Трассах» — ближайшие 40 (от домашней трассы, иначе из страны профиля или часового пояса) и «Показать ещё»; домашняя трасса (профиль, первый вход) — из выбранной страны; трасса в правке сессии — в 300 км от заезда, ближайшие первыми; выбор конфигурации в Hutka AI — твои и где катаются, ближайшие с линией, остальные поиском; в админке — поиск по трассам; «мозг» обновляет только конфигурации с сессиями.
- Тесты: t107_osmtracks (трасса с карты: страница, идеальный круг, загрузка Alfano находит её по линии; 3000 трасс: каталог, «ещё», поиск, выбор конфигурации, домашняя трасса), t108_realosm (пять настоящих трасс из импорта на телефоне: линия, длина, повороты), importtest/test_lib.mjs (склейка площадки, своя петля, направление), test_qlever.mjs (ответы QLever → площадки), test_names.mjs (картинговые названия на языках карты и не-картинг).

### Любая картинка трассы, у любого человека (v34.38)
- **Обводка — одна система для всех картинок** (`at.js`, `AT.best`): пробуются собственные цвета картинки (тонированные — по оттенку, в пределах ±95 по яркости: блик и тень полосы да, белая бумага того же оттенка нет; серые — по цвету), затем «всё, что не фон», «всё тёмное» и адаптивные «темнее/светлее своего окружения» (фото при неровном свете). Маска читается и на копии до 1800 px — тонкая линия трекера/приложения не рассыпается при уменьшении; полосы берут края с рабочего размера (ноги шпильки не слипаются).
- Общие правила вместо подгонки под картинку: мелочь убирается по размеру (тонкая линия остаётся); трасса, нарисованная двумя краями, или полоса с травой/линиями по обеим сторонам — кольцо между двумя параллельными кольцами заливается; разорванные концы (мост, стартовая клетка, подпись) сшиваются; толстые нашлёпки (плашка заголовка, легенда) отрезаются; кольцо у края картинки и «четыре прямые стороны» (лист бумаги на столе, рамка экрана) — не трасса, берётся следующее; полоса, у которой что-то идёт вдоль одной стороны (трава, кромка), — окантовка, трасса — то, что между окантовками; цвет по середине лучшего кольца пробуется отдельно (трасса внутри своей травы).
- Проверка — набор картинок с известной правильной линией (`scratchpad/corpus*/gen.py`, `run.js`): реальные формы (40 трасс F1 + конфигурации Dubai Kartdrome) в 8 стилях — полоса на фоне, план площадки с выделенной конфигурацией, только два края, тонкая линия трекера, сектора/градиент скорости, тёмное приложение, линия поверх карты города, фото распечатки (перспектива, свет, размытие, JPEG). Два независимых набора по 64: 59/64 и 61/64 (было 36/64); обе официальные схемы Dubai — как в v34.37; около секунды на картинку.
- **Видно, что прочитано**: на карточке миниатюра картинки с прочитанной линией и «Не та линия? Ткни в трассу» — картинка крупно, тап по нужной полосе читает её (цвет под пальцем, ближайшая полоса); тап мимо — «там нет трассы».
- **Трасса не из Hutka, но есть на карте OSM**: прочитанная схема накладывается на петли OpenStreetMap этого места (`TRACKFIND.loopFit`) — настоящие метры («размер — по карте»).
- **Без входа**: ИИ читает схему и у незалогиненных (функция `ask`, `identify_track`): 5 фото в сутки с одного адреса сети (короткий хэш), 200 в сутки на всех гостей (`LIMIT_VISION_IP_DAY`, `LIMIT_VISION_ANON_DAY`); миграция `20261019200000_vision_visitors.sql` (`ai_vision.user_id` может быть пустым, колонка `ip`). Чат по-прежнему только со входом.
- Тест t99i_any (гость: схема Speedway → Speedway 824 м с миниатюрой; тап мимо и по полосе; трасса вне Hutka в пределах 5 % от длины на карте).

### Схема площадки: нужная конфигурация сразу, в настоящих метрах; трасса по названию — сразу гид (v34.37)
- **Фото/скрин официальной схемы** («SPEEDWAY CIRCUIT», «INTERNATIONAL WITH BUS STOP»: все конфигурации площадки серым, нужная — своим цветом, подписи T1…T20, стрелки, мост): Hutka AI → Новая трасса → «Фото схемы трассы». ИИ читает площадку **и название конфигурации** с заголовка схемы; Hutka открывает именно её: если по ней есть круги — идеальный круг из реальных кругов, если нет — схема обводится и ложится на проеханные конфигурации площадки.
- **Обводка** (`at.js`): выделенная конфигурация берётся по оттенку (блики и тень под мостом — тот же оттенок), подписи и стрелки внутри полотна заливаются, дорога под мостом сшивается через мост (концы полотна, смотрящие друг на друга), осевая обходится как граф — на перекрёстке прямо, вокруг стрелки по более прямой стороне (`AT.best`: по рамке, по тёмному, по каждому основному цвету; выбирается самое «трассовое» кольцо). Обычные рисунки обводятся как раньше; восьмёрки (мост) теперь целиком.
- **Настоящий размер** (`TRACKFIND.venueFit`): обводка подбирается к GPS-линиям конфигураций площадки (масштаб, поворот, сдвиг — голосованием по парам точек с одинаковым направлением, потом уточнение по ближайшим точкам). Speedway на 92 % лежит на International → 824 м, старт/финиш площадки, направление — со стрелок схемы, из настроек конфигурации или как ездят International на общих участках. Посторонний рисунок к площадке не «прилипает» (нужно ≥ 75 % обводки на линии и заметное покрытие); если на картинке напечатана длина и подбор с ней не согласен — берётся длина с картинки.
- Без заголовка: форма схемы целиком на конфигурации → открывается она; частично → «Такой конфигурации ещё нет» и линия по схеме в масштабе площадки.
- **Админ: «Сохранить в конфигурацию»** — линия Speedway (`photoLine`, `how: 'venue'`, длина в метрах) у всех открывается сразу.
- **Трасса по названию** («Dubai Kartdrome»): сразу открывается идеальный круг основной конфигурации (International / Full / Main…, у которой есть линия); если площадки на Hutka нет — самая длинная трасса с карты OSM, по часовой (вторым нажатием — против). Список остальных вариантов остаётся под ним. Фото схемы нужно, только если трасса не нашлась. Площадка на Hutka ищется и по укороченному названию («Dubai Kartdrome, Dubai, UAE» → Dubai Kartdrome), без карты.
- Функция `ask` (identify_track): в ответе ИИ поле `layout` — название конфигурации со схемы.
- Тест t99h_plan (обе официальные схемы Dubai Kartdrome: Speedway сразу и 824 м, сохранение, водитель видит линию; International w Bus Stop — сразу реальные круги; без заголовка — по форме; «Dubai Kartdrome» — сразу International; загрузка схемы в «Идеальный круг · Speedway»).

### Реверс — это та же конфигурация в обратную сторону (v34.36)

### Лучшая траектория по схеме конфигурации (v34.35)
- **«Идеальный круг» конфигурации, где никто не ездил и нет рисунка**, — одна кнопка «Загрузить схему». Картинка схемы (скриншот, фото карты) обводится (`at.js`: полотно трассы → осевая), размер — по длине круга с картинки (ИИ читает её и направление по стрелкам) или оценка; направление — из настроек конфигурации, со стрелок или по часовой, вторым нажатием — против. Повороты и точки читаются на этой линии (атласы учились на проеханных линиях), на карте — полотно трассы серым и линия синим, в легенде «Траектория». Прежняя «резинка» (кратчайший путь) убрана.
- **Сохранить в конфигурацию** (админ или редактор трассы): схема сохраняется в конфигурацию (`photoLine`: осевая через ~2 м в метрах, длина, ширина, направление) — у всех «Идеальный круг» этой конфигурации открывается сразу, с пометкой «По схеме конфигурации». ### AiM, чужая конфигурация, метры, новая трасса по фото (v34.32)
- **AiM (MyChron, Solo, EVO) — родной файл `.xrk` (и упакованный `.xrz`).** Читается как есть, без экспорта из Race Studio: GPS 25 Гц (u-blox NAV-SOL: позиция и скорость в ECEF), круги — из блоков LAP логгера (время круга — логгерное, до тысячной), обороты и температура воды (T.1) — из каналов `(S`, кусок круга в боксах (20 с в конце) отбрасывается, дата — по GPS-неделе. С оборотами класс карта — спорт (прямой привод). Название трассы из файла (`RAK T-Shape`) находит трассу Hutka, даже если её точка на карте в 3,6 км. В окне загрузки `.xrk/.xrz` выбираются сразу (и в «Поделиться» на телефоне); старый `.drk` — понятная просьба экспортировать CSV. MyChron по Bluetooth сессии не отдаёт: если браузер не видит у прибора ни одного сервиса, окно прибора не предлагает «отправить лог», а одной кнопкой ведёт к загрузке файла. Тест t99_aim (файл Rayyan, RU/EN).
- **Сессия с чужой конфигурации больше не портит конфигурацию.** Кроме доли круга «мимо линии» (> 20 м, ≤ 12 %) проверяется, насколько круг уходит вбок: 95-й процентиль бокового отклонения от линии ≤ 9 м (на своей конфигурации ≤ 6,4 м, та же трасса с бас-стопом или без — 11–20 м; для GPS телефона ×1,5; только против линии из реальных кругов). Если лучший круг сессии выпадает (скачок GPS), проверяется средний чистый круг. Так проверяются сравнения в Лаборатории, дуэль, распознавание конфигурации при загрузке и мозг. BRAIN.VER = 3 — атласы пересоберутся у админа. ### Hutka AI и мозг — превью для админа (v34.31)
- **Мозг (brain.js, app_brain.js).** Учится на лучших реальных проездах: для каждой конфигурации и класса карта (прокат / спорт) — «атлас поворотов»: форма поворота (угол, радиус, прямые до и после, связка с соседним) и что делают самые быстрые (до 8 лучших проездов на поворот, не больше трёх от одного пилота). Точки — как говорят пилоты, в корпусах (2 м): тормоз/сброс от входа в поворот, отпустить тормоз, газ (где карт перестаёт замедляться — у топов у апекса или раньше), в пол (где уверенно разгоняется) — от апекса. Линия конфигурации — по самому быстрому прокатному кругу (линия спортивного карта другая). ### Проверка на баги и недоработки (v34.29)
Четыре независимые проверки (без сети; загрузка → черновик → карточка; прибор по Bluetooth; тексты и маленькие экраны) и бэкенд. Каждая находка воспроизведена скриптом, после правки скрипт прогнан снова.

**Без сети и очередь на телефоне**
- Без сети запросы к базе отказывают сразу: у supabase-js выключены повторы (были 1+2+4 с на каждый запрос), у каждого запроса таймаут (чтение 20 с, запись 90 с), вход без сети — из сохранённого токена без запроса на сервер. Выход без сети чистит сохранённый токен.
- Черновики сохраняются по одному (и между вкладками — `navigator.locks`): окно загрузки, очередь и вторая вкладка не сохранят одно чтение дважды. Пока после возвращения связи токен не обновился, сохранение ждёт на телефоне (раньше библиотека читалась «как гость» и сохранение получало отказ).
- Запись сессии есть, а телеметрии нет (связь оборвалась между двумя запросами) — при следующей загрузке телеметрия дописывается в ту же запись.
- После отказа сервера (лимит) возвращение в приложение не отправляет файл заново раньше срока (2, 4, 8… до 30 мин), «Upload now» — сразу. Браузер просится не чистить хранилище (`navigator.storage.persist`). Список прибора обновляется, когда очередь ушла.
- Библиотека без сети — последняя известная (`cache:mine:<uid>`); список прибора так и пишет: «No connection — sessions already in Hutka are recognised from what this device saw last time.»
- Service worker `hutka-shell-v93`: в кэш попадают только удачные ответы (404/500 не затирают рабочую копию), одна копия на файл (адрес с `?…` — та же страница), на медленной сети страница берётся с телефона через 3,5 с. Тест t95 теперь выключает сервер на время старта без сети (раньше страница могла прийти по сети) и проверяет медленную сеть (12 с → старт за ~4 с).
- Гость при возвращении связи не ждёт 70 с токена, которого у него нет.

**Загрузка → черновик → карточка «Finishing touches»**
- Одно чтение прибора с разных трасс — каждая трасса своей пачкой (раньше всё шло на трассу первого файла). Линия новой конфигурации — только от уверенно узнанной сессии с ≥ 2 чистыми кругами, не от догадки; выбрал гонщик конфигурацию без линии — линия от его сессии.
- Дубли: дата берётся из файла внутри .alf2, если сам файл переименован; у GPX/CSV — время старта записи; один файл дважды в одном выборе; RaceBox — по старту в UTC (чтение в другом часовом поясе — та же сессия, `startMs` в мете).
- Карточка: «Publish N sessions» публикует только сессии с той же или уверенно узнанной конфигурацией (догадку за гонщика не публикует, тост говорит, сколько осталось приватными); выбор конфигурации не переписывает уверенно узнанные; ошибка сохранения видна (раньше ✓ без сохранения); записи по одной сессии идут по очереди (чипс и сразу Publish — сохраняются оба); место — целое и не больше числа гонщиков; «Not in the list ✓ your pick»; у трассы нет конфигураций — вопроса нет.
- Публикация любым путём (кнопка в Лаборатории, списки, окно Edit) снимает черновик — карточка не появляется у опубликованной; скрытую админами сессию нельзя опубликовать заново и через окно Edit; смена конфигурации в Edit — выбор гонщика.
- Нечитаемый файл из выбора — в тосте после открытия (раньше пропадал с окном); адрес страницы — `#lab~<id>`, перезагрузка открывает сессию. Загрузка, пришедшая во время другой (чтение прибора закончилось, пока сохраняется файл), ждёт очереди, а не теряется.

### Сравнение решает линия, а не подпись (v34.28)
Баг от Уладзислава 18 окт: сессии Паши с Al Forsan (5-часовая гонка 10 окт) — «other layout» рядом с его сессией той же гонки; свои сессии Int+Busstop тоже не сравнивались.
- **Причина 1 — дубль трассы.** У `al-forsan` булавка стояла на адресе курорта, в 6,5 км от трассы; загрузка Паши 17 окт (правило «ближайшая трасса в 3 км») её не нашла и открыла вторую страницу «AL FORSAN INTERNATIONAL» (`txmvc0p64btelr1`), туда ушли 4 его сессии. Данные поправлены: координаты `al-forsan` — по центру кругов (у двух гонщиков совпадают до метра), 4 сессии Паши перенесены на Al Forsan · International (`full`), карточка и превью пересоберутся. Пустой дубль оставлен (по решению Уладзислава), новые загрузки на него не попадут.
- **Причина 2 — подписи.** Две сессии Уладзислава записаны без конфигурации (`custom`) — это копии сессий на International w Bus Stop; у Клинта таких 5. Сравнение шло только по совпадению `track/layout`.
- **Теперь в списке «Another session…»** сессия, записанная под другой конфигурацией или другой страницей трассы, но проехавшая там же (центр кругов ближе 2 км), проверяется по самой линии — тем же распознаванием, что и при загрузке (`detectLayout`: лучший чистый круг против линии каждой конфигурации трассы). Совпала — зелёная «same line», сравнивается; нет — «other layout» (как раньше, правило Паши: разные конфигурации не сравниваются); другой город — «other track». Для сессии без конфигурации её линия определяется так же, и в список попадают опубликованные сессии этой конфигурации. Проверка идёт фоном после открытия списка («checking…»), не больше 12 загрузок, результат кэшируется.
- **Загрузка ищет трассу по линии.** `trackFor`: сначала трассы в 15 км, у конфигураций которых линия совпадает с кругами; потом название из прибора («AL FORSAN INTERNATIONAL» ↔ «Al Forsan International Sports Resort», без общих слов и названия города); потом ближайшая в 3 км; и только потом новая страница. Булавка трассы может быть хоть в 6,5 км — сессия ляжет куда надо.

### Запуск без интернета (v34.27)
Продолжение пункта 9: приложение открывается на трассе и без связи.
- **Сайт в телефоне.** Service worker теперь работает и внутри приложения (раньше был выключен в Capacitor): страница, `config.js`, `supabase.js`, логотипы лежат в кэше `hutka-shell-v92`; без сети приложение стартует из него (страница — сначала сеть, потом кэш, так что обновления приходят сразу). Самый первый запуск без сети — по-прежнему `offline.html`.
- **Вход не теряется.** Если токен истёк, пока не было связи, supabase-js не отдаёт сессию, хотя она лежит в `localStorage`. Когда связь вернулась и токен обновился (`TOKEN_REFRESHED`), исходящие уходят сразу; пока токен не живой, они ждут, а не получают отказ RLS.
- **Трассы помнятся.** Список трасс сохраняется в IndexedDB (`kv`, `cache:tracks`) и подставляется, если сеть не ответила. Черновик сохраняется только на свежем списке из базы (`STORE.ensureTracks`) и на свежей библиотеке (`STORE.mySessionsStrict`): без связи — ошибка и ожидание на телефоне, а не вторая страница трассы и не дубль сессии. Неудачная загрузка конфигураций и профиля больше не запоминается как «пусто»; форма «Welcome to Hutka» не открывается, если профиль не удалось загрузить.
- **Видно, что связи нет.** Под шапкой на любой странице — строка «No internet — reading the lap timer still works; the sessions upload by themselves once the connection is back.»; «My sessions» и лента пишут «No connection…» вместо «пока ничего нет». Связь вернулась — строка уходит, списки на открытой странице подгружаются.

### Лаборатория для новичка, часть 1 (v34.14): референс по умолчанию, оценки поворотов, «с прошлого раза», рейтинг карта

### Чтение с прибора: контрольные суммы, повтор и откат блока (v34.11)
После v34.9 два чтения на настоящем приборе пришли битыми (сессии 17 окт 12:00 и 12:05 UTC: лучший круг 28 с, координаты в Иране): модуль RN4678 теряет байты, когда ответ в 4 КБ обгоняет линк, а `stripXor` просто выкидывал каждый 257-й байт — сдвиг на один байт превращает все поля в мусор. Теперь (`alfano7.js`):
- каждый пакет ответа проверяется по своему XOR (`packetsOk`; правило проверено на сырых дампах Паши); битый ответ запрашивается снова, после двух подряд битых размер блока делится пополам, после четырёх — ошибка `corrupt` с диагностикой в `device_logs`;
- блок по умолчанию 4 пакета (1 КБ), не 16; проба «сколько прибор отдаёт» осталась;
- ожидание ответа заканчивается, когда ответ перестал приходить (1,5 с тишины), а не по таймауту в 10 с — оборванный ответ стоит пару секунд;
- после чтения сессии — проверка смысла (`sanity`: доля строк с невозможными числами); > 2 % — чтение не отдаётся, пользователю «ответы прибора пришли повреждёнными — попробуй ещё раз», диагностика в `device_logs`.
Список «Другая сессия…» на телефоне: строка в две линии — имя гонщика целиком, название сессии с многоточием и время, плашки «same layout» / карт ниже (раньше имя обрезалось до двух букв). Эмулятор умеет терять байт в больших ответах (`img.lossyBig`); `t74_alfano_blocks.js` проверяет, что с таким линком ZIP всё равно байт в байт тот же (откат до 2 пакетов). Осевая линия конфигурации — средняя линия эталонной сессии (первой опубликованной на конфигурации; на Dubai standard это сессия Грега, январь). - целый круг рисуется по его записанному пути, всеми точками (`P.lap.px`); по станциям — только отрезки (повороты) и маркеры; у проекции появились `P.x/P.y` — положение круга на станции по времени прохождения (`t[i]`), с лёгким сглаживанием ±1,5 м на стыке конца и начала круга; `DATA.lapXYAt(tr, P, i)` — одно место для «где круг на станции» (карта, карточка, лендинг);
- проекция устойчивее: первая точка круга ищется по всей петле (S/F другой сессии — где угодно), окно поиска при потере машины (> 20 м от осевой) едет вперёд по скорости, а не стоит; часы круга пересчитываются к станции 0 (S/F конфигурации), чтобы времена всех кругов начинались в одном месте; доля потерянных точек — `P.lost`;

### Чтение с Alfano в несколько раз быстрее (v34.9)
Почему было медленно: приложение Alfano просит у прибора по 512 байт за команду (`_taille_max_buffer` из APK), и мы делали так же; по классическому Bluetooth (SPP, Android-приложение ADA) команда стоит миллисекунды, а по BLE каждая команда — это 258-байтовый кадр в 13 записях по 20 байт через мост плагина плюс ожидание ответа, то есть ~0,3 с на 512 байт: сессия на 47 кругов (~800 КБ) читалась 9 минут. Две вещи в `alfano7.js` / `device.js`:
- **Длинные записи.** При входе пароль сначала отправляется кусками по 180 байт (два вызова моста на кадр вместо тринадцати — iPhone даёт MTU 185, Android 14+ сам договаривается о 517). Нет ответа за 2,5 с (линк отказал или обрезал запись) — пауза 1,5 с, чтобы прибор выбросил полкадра, и дальше по 20 байт, как раньше (`pipe.piece`). Эмулятор умеет отказывать и обрезать (`__rb.mtu`, `__rb.mtuMode`), у его парсера есть таймаут между байтами, как у UART — тест `t75_long_writes.js`.
- **Большие блоки.** `bulk()` просит до 16 пакетов (4 КБ) за команду вместо 2. Первый большой запрос — проба: ответил меньше (или ничего) — столько и просим до конца сеанса, а перед следующей командой ждём тишины в линке, чтобы хвост не попал в следующий ответ. На дампе Паши все варианты (16 / 7 / 2 / молчит на большие) дают один и тот же ZIP байт в байт, команд на 28-круговую сессию 157 вместо 1100 — `t74_alfano_blocks.js`; `t70` по-прежнему 156/17 против официальных экспортов.
Предел теперь — UART между модулем RN4678 и процессором прибора (~115200 бод ≈ 10 КБ/с), то есть минута-полторы на 47 кругов вместо девяти. Пауза между командами 10 мс вместо 30.

### Alfano 7 по Bluetooth — сессии с прибора в Лабораторию (v34.7)
`alfano7.js` (`ALFANO7`) — протокол прибора и декодер: по материалам Pavel Go-ski (PROTOCOL.md из декомпилированного приложения Alfano, github.com/TheAngryRaven/alfano-bt-spec). Прибор говорит через модуль Microchip RN4678 — обычный последовательный мост; приложение Alfano ходит в него по классическому SPP, Hutka — по BLE-«прозрачному UART» того же модуля (сервис `49535343-fe7d…`, вход `…8841`, выход `…1e4d`), поэтому работает в Chrome (Mac/Android) и в приложении на iOS и Android. Команды — кадры по 258 байт (опкод, аргументы, нули, XOR): пароль `000000` (0x2D), статус (0x36), страница EEPROM (0x2B, 129 байт), чтение flash (0x17, n × 257 байт). Сессии — страницы EEPROM 0xB4+ (адреса, круги, лучшее время); у сессии во flash заголовок 306 байт (PARAMETRE.dat), записи границ кругов (PARTIEL, 94 байта: адрес, время, Vbat, HDOP) и телеметрия 22 байта/10 Гц. Два порядка PARTIEL (с секторами / без) как в приложении. Декодер пишет тот самый ZIP, что экспортирует приложение Alfano (PARAMETRE.dat, итоговый CSV с временами кругов и секторов, LAP_n.csv с Gf.X/Gf.Y по формулам приложения, lap_theorique.csv, EEPROM-страницы) — на дампе памяти прибора все файлы кругов и итоги совпали с оригинальными экспортами байт в байт (`t70_alfano_node.js`; отличия только в заезде в боксы, который мы ограничиваем 30 КБ, и в погоде/времени). Файл уходит в обычную загрузку как `ALFANO7_LAP_….alf2`.
Окно «С прибора» → Alfano: список приборов → подключение → вход → список сессий (дата, трасса, гонщик, круги, лучшее) → галочки → чтение с прогрессом по кругам → форма загрузки → Лаборатория. Если прибор не принял пароль или у него нет последовательного сервиса — автоматически разведка (лог в device_logs). Эмулятор прибора для тестов — `alf_emu.js` (в Node и в браузере), тесты `t70_alfano_node.js` (протокол + декодер против экспортов), `t71_alfano_app.js` (приложение целиком).

### Квоты, защита от выгрузки и ночные копии (v34.4)
`supabase/limits.sql` (миграция `20261017090000_limits.sql`):
- **Телеметрия только через функцию** `hutka_session_data(sid, vid)`: таблица `session_data` напрямую читается теперь только владельцем. Функция считает открытия в `quota` (одна строка на ключ и день, upsert): вошедший — 600 в день, гость — 150 в день на адрес (`hutka_who`: аккаунт → `x-forwarded-for`/`cf-connecting-ip` → visitor id). Свои сессии и админы не считаются. Наблюдавшийся максимум до этого — 13 открытий Лаборатории в день (≈100–150 загрузок с референсами и сравнениями). Сверх лимита Лаборатория пишет «Daily limit … reached». Клиент: `adapter.getChunks` → rpc; без функции (старая база) откат на таблицу.
- **Квоты на запись** (триггер `hutka_quota_guard` before insert, админы и service role не считаются): сессии 60/день, комментарии 200/день и 15/мин, лайки 500/день и 15/мин, подписки 200, жалобы 50, блокировки 100, трассы 20, лейауты 40, заявки 10, чаты 100. Отказ — `exception 'quota'`; страницы показывают «Daily limit reached».
- **Анонимные счётчики**: `hutka_event` ≤3000/день на visitor id, `hutka_visit` ≤300 — сверх молча отбрасывается. Счётчики `quota` чистятся через 2 дня (`hutka_quota_sweep`, pg_cron 03:00 UTC).
- **Ночные копии** `hutka_snapshot()` (pg_cron 02:20 UTC): все таблицы копируются в схему `backup` (`backup.dYYYYMMDD_<table>`), телеметрия хранится 3 дня, остальное 7. Админка → «Nightly snapshots». Это защита от своих же ошибок и багов, не от потери проекта — для этого Supabase Pro (ежедневные бэкапы). При росте телеметрии (>100 МБ) копии начнут есть место базы — тогда переходить на Pro и убирать `session_data` из списка.
- **Капча (Cloudflare Turnstile)** подготовлена в клиенте (`CAPTCHA` в app_core.js): когда в `config.js` появится `turnstileSiteKey`, виджет появится на входе по почте/паролю и токен уйдёт в Supabase. Включать: Cloudflare → Turnstile → Add site (hutka.ai, тип Managed) → site key в `config.js`, secret key в Supabase → Authentication → Attack protection → Enable Captcha (Turnstile). Google/Apple вход капчей не трогается.

### Кокпит в приложении Android: системные полосы и полный экран (v34.1)
- Все отступы безопасной зоны идут через переменные `--sa-top/right/bottom/left` (`:root` — `env(safe-area-inset-*)`). В Android-приложении `html.android` читает `--safe-area-inset-*`, которые Capacitor (SystemBars, `insetsHandling: "css"`) вставляет с реальными значениями статус-бара, навигационной панели и выреза — `env()` на части WebView их не знает, и крестик инспектора в ландшафте оказывался под навигационной панелью справа («мёртвая зона»). Крестики инспектора и пикера, вкладки и панели справа теперь отступают от статус-бара сверху и от панели/выреза справа.
- Полный экран больше не делает `#hero.requestFullscreen()`: один элемент в top layer прятал всё, что вне него — share-лист, тренера и список поворотов (на Android они открывались «под» картой). Теперь полный экран = CSS-раскладка `fs-fallback` (хиро поверх страницы, модалки/панели/тосты над ним по z-index), а в браузере (не в приложении) к ней добавляется `document.documentElement.requestFullscreen()` — уходит только браузерный хром. Esc / системная «назад» / кнопка выхода снимают оба.
- Телефон боком: share-лист ужат (превью ≤46vh), кнопки видны без прокрутки. Подписи на карте (тормоз/апекс/газ) держатся внутри свободной части холста (под плашкой лендинга, вне HUD кокпита) и, если снаружи поворота места нет, встают с внутренней стороны.

### Alfano 6 на спортивном карте: обороты, передачи, переключения, вода (v32)
Экспорт Alfano 6 (zip из приложения ADA, `LAP_n_*.csv` с колонками RPM, T1, T2) читается тем же импортом, что и .alf2; в точках круга появляются `rpm` и `t1`/`t2` (°C), в данных сессии они хранятся форматом v2 (`store.js` `packLaps`: заголовок перечисляет каналы круга), старые сессии не меняются. Каналы, которых у логгера нет (прокатный Alfano 7 пишет RPM 0), отбрасываются при импорте, поэтому прокатные сессии остаются ровно такими же — ни одного нового элемента без данных двигателя.
- **Коробка** (`gear.js`): по всей сессии считаются уровни отношения скорость/обороты (GPS-скорость отстаёт от оборотов на ~0.2–0.3 с, лаг подбирается по корреляции). DD2 — два уровня, KZ — до шести, одноприводные Rotax MAX / X30 — один (переключений нет, только обороты). Класс карта из загрузки (Rotax DD2, KZ2, X30…) — подсказка числа передач; без класса — по данным (1 / 2 / 6). Переключение вверх = уровень вырос и обороты провалились (отношение подскочило ≥ половины шага) за 0.3 с; вниз — наоборот при торможении. У Грега (DD2, Dubai, 12 чистых кругов): ровно 4 ▲ и 4 ▼ на каждом круге, вверх на 12 600–13 500 об/мин, вниз на 79–96 км/ч.
- **Lab:** маркеры ▲ (жёлтый) / ▼ (фиолетовый) на линии круга с номером новой передачи (при приближении), у остальных кругов — на их линиях в их цвете; подписи «upshift → 2 · 12 900 rpm» / «downshift → 1 · 87 km/h» у выбранного поворота; панель **rpm** под графиком скорости (трасса оборотов всех кругов, полосы передач с номерами, маркеры переключений, вода пунктиром по правой оси); в инспекторе строки **gear / downshift / upshift / revs / water**; чипы `rpm max`, `gears 2 · DD2`, `shifts 4 ▲ · 4 ▼`, `water 47–55 °C`; абзац **Engine** в дайджесте (в т. ч. повороты с переключением вниз и «у сравнения переключение на N м раньше/позже»); обороты и передача в чипах реплея и в HUD кокпита; у среднего круга — «типичные» переключения (кластеры по месту, не меньше чем у половины кругов); идеальный круг наследует обороты и переключения выигравших кругов. ИИ-тренер получает блок `engine` и по поворотам `revs_min/max`, `gears`, `downshift`, `upshift`, `water_c`.
- **Лента:** у сессии с оборотами чипы `rpm max`, `shifts N / lap`, `water` (из `meta.ch`, без загрузки данных).
- Передачи нумеруются от верхнего уровня (у DD2 1–2; у KZ верхний = 6-я, широкий разрыв между уровнями = пропущенная передача). Редактирование карта сессии пересчитывает коробку.

Точки действий меньше и чуть прозрачные (тормоз 4.2 px, газ 3.4, апекс 2.7 при обычном масштабе, растут с зумом совсем немного), номера поворотов — кружки 9 px с полупрозрачной заливкой и обычным начертанием (выбранный — 12 px, жирный), маркеры-«карты» — точки 6–7 px с тонкой цифрой. На спутнике при приближении с телефона всё читается, а не сливается.

### Три круга, карты-«карты» и реплей (v31)
Как в плеере Alfano ADA: на карте до трёх кругов, у каждого свой цвет и номер — 1 опорный (синий), 2 сравнение (розовый), 3 третий круг (бирюзовый, `--cmp2`). Третий круг выбирается в полосе выбора («Третий круг (необязательно)», появляется, когда включено сравнение) — любой круг или средний любой загруженной сессии, в том числе другого гонщика (подгружается через «Another session…»). Линии стали тоньше; все точки (тормоз, сброс, отпускание, апекс, газ) рисуются для выбранного круга (кнопки «1 · Reference / 2 · Comparison / 3 · Third lap» или клик по чипу круга), у остальных на их линиях остаются точки торможения и сброса — кольцами в цвете круга. Разбор по-прежнему парный (опорный vs сравнение: тексты, дайджест, тренер), третий круг — визуально и цифрами: колонка «3» в инспекторе, «3: +0.08» в таблице поворотов и в списке на телефоне, чип в шапке, линия на графике скорости и в графике Δt, строка в HUD кокпита, поле `third_lap` / `third_time` в контексте ИИ.
**Реплей.** Под картой — полоса: ▶, ползунок по времени, время и чипы кругов с живыми цифрами (метры, скорость, Δ к опорному). Каждый круг — свой маркер-«карт» с номером на своей линии; ползунок двигает их по времени, так что быстрый уезжает вперёд, как у Alfano; ▶ проигрывает круг в реальном времени. Наведение мыши на карту или график ставит все маркеры на одну точку трассы (сравнение по месту), ползунок — по времени. В кокпите (телефон боком / полный экран) полоса внизу тоже стала временной: три точки на графике скорости, в HUD метры у каждого свои, время общее. Маркеры и на графике скорости.
Что осталось как было: наведение и выбор поворота, подписи, бейджи, корridor, шаринг (карточка — только опорный круг).

### Из чего состоит идеальный круг (v30.3)
Под таблицей поворотов при «Best vs ideal» — блок **Ideal lap breakdown**: по каждому повороту три самых быстрых круга сессии с временем в этом повороте (лучший — зелёный, пунктир — сам лучший круг), справа — время лучшего круга и сколько он проигрывает; внизу Σ лучших поворотов и лучший круг. Нажатие на круг делает его сравнением и закрепляет поворот — видно, что в нём было сделано иначе (и можно найти круг на камере); блок при этом не пропадает, пока не выбран другой режим сравнения. Пометка про приблизительность — в самом блоке, в дайджесте и всплывающей подсказкой при выборе. Из полосы выбора пометку убрал: она меняла высоту полосы при каждом переключении и «дёргала» страницу. Свёрнутая (прилипшая) полоса теперь не накладывает чипы сравнения на список «Compare with»: чипы держат ширину, выбор сессии в свёрнутом виде скрыт.

### Лучший vs идеальный круг (v30.2)
В Lab, рядом с «Best vs average», — **Best vs ideal**. Идеальный круг сессии: в каждом окне поворота (отрезок от одного пика скорости до следующего, так что окна покрывают весь круг) берётся самый быстрый проезд среди чистых кругов, и всё это сшивается в один круг — его время, линия и точки. Сравнение показывает по каждому повороту, какой круг его выиграл: в таблице поворотов («lap 26 · …»), в инспекторе (заголовок колонки и строка «Твой самый быстрый проезд: круг 26, 4.31 с, на 0.18 с быстрее»), в дайджесте — список «Где другой круг был быстрее: T10 — круг 43 (−0.35 с), …» с переходами в поворот. Пометка про приблизительность — везде: под чипами сравнения, в дайджесте (выделенный блок) и в инспекторе: повороты оцениваются по одному, связки не учитываются, такой круг целиком никто не проезжал — потолок, а не цель. Доступно, когда опорный круг — реальный круг этой же сессии (не средний) и чистых кругов ≥ 2; в списке «Compare with» идеальный круг тоже есть. ИИ-тренер получает флаг `comparison.ideal` и `comparison_lap` по поворотам.

### Превью ссылки на сессию (v30)
Ссылка на сессию теперь `hutka.ai/s/<id>` — у каждой опубликованной сессии своя маленькая статическая страница с Open Graph-тегами: заголовок «Имя — 1:15.030 · Dubai Kartdrome», строка с результатом / средним / кругами / картом, и картинка 1200×630 (лучший круг с точками Lab, номера поворотов, время, плашка результата). Страницы пишет функция `share-page` в репозиторий GitHub Pages (`s/<id>.html`), картинки лежат в публичном бакете Supabase `cards/<uid>/<id>.png`. Строится один раз — когда владелец открывает опубликованную сессию в Lab (после загрузки — само), при «Поделиться», при публикации из списков; перестраивается после правки (название, результат); при снятии с публикации страница и картинка удаляются, ссылка снова `#lab~<id>`. Старые опубликованные сессии получают страницы в фоне на Home: свои — с картинкой, чужие (у админа) — пока с общей картинкой, своя появится, когда автор откроет сессию. Первые ~30–60 с после публикации страница ещё деплоится на GitHub Pages — ссылка уже работает (404-страница переводит в Lab), превью появится, когда деплой закончится. `meta.share = {key, img, imgKey, page, url, at}` помнит, что построено.

Чтобы включить:
1. Бакет `cards` + функция `hutka_set_share` — миграция `supabase/migrations/20261017130000_share.sql` (применена 17 окт; `supabase/share.sql` — старая версия без политики админа, справочно).
2. Токен GitHub: github.com → Settings → Developer settings → Personal access tokens → Fine-grained → Repository access: только `ukazyra-collab/hutka` → Permissions → Contents: Read and write → Generate (если репозиторий в организации и fine-grained запрещены — classic token со scope `repo`).
3. Supabase → Edge Functions → Secrets: `GITHUB_TOKEN` = токен. Необязательно: `GITHUB_REPO` (по умолчанию `ukazyra-collab/hutka`), `SITE_URL` (`https://hutka.ai`).
4. Задеплоить функцию `share-page` (Edge Functions → Deploy via Editor → вставить `supabase/functions/share-page/index.ts`, Verify JWT — выключить).
5. Открыть Home один раз — фон построит страницы для уже опубликованных сессий.

- Страница трассы = страница лейаута: вкладки лейаутов (Standard · Extended · …), карта с corner guide, переключатель «чей круг показать», сессии на этом лейауте, ниже — остальная информация о трассе. Старые ссылки `#layout~…` открывают эту же страницу.
- Меню: Главная → Lab → AI-тренер → Трассы → Профиль. Личные рекорды в профиле — плитками (трасса · лейаут · карт · время).

### Безопасность (v27) — что сделано и что включить руками
Что уже в коде и в SQL (`supabase/security.sql`, запустить один раз, безопасно повторять):
- Доступ к данным держат политики RLS: приватные сессии видит только владелец, чужие строки никто не правит; роль `anon` вообще не может писать.
- Админ — только тот, чья почта из `admin_emails` **подтверждена** (регистрация на чужой адрес без подтверждения ничего не даёт).
- Идентификаторы и тексты проверяются в базе (формат id, длины имён, размер картинок и сессий), лайки и комментарии нельзя оставить к несуществующей сессии, они удаляются вместе с ней, владельца строки нельзя переписать.
- Лимиты на аккаунт: сессии 150/день, трассы 20/день, комментарии 60/час, оценки 300/час, подписки 300/день, запросы на трассу 10/день (админов не касается).
- Edge-функции: проверка JWT, лимиты ИИ (в час/день/на адрес/на всех), ключ Anthropic не может быть использован «не по теме» (серверная рамка в промпте), Stripe-вебхук с проверкой подписи, возврат после оплаты только на наш сайт.
- На сайте: всё, что ввели люди (имена, подписи, комментарии, названия), экранируется; внешние ссылки — только http(s); CSP запрещает плагины и подмену base.

Включить в панели Supabase (5 минут):
| Где | Что |
|---|---|
| Authentication → Sign In / Providers → Email | **Confirm email — ON**, **Secure email change — ON**, минимальная длина пароля 10 |
| Authentication → Attack protection | **Prevent use of leaked passwords — ON** (есть на Pro), CAPTCHA (Turnstile) — по желанию, когда пойдёт спам регистраций |
| Authentication → URL Configuration | Site URL `https://hutka.ai/`, Redirect URLs — только свои (`https://hutka.ai/**`, `hutka://auth`), без `*` в других местах |
| Project Settings → API | `service_role` ключ никуда не копировать; в `config.js` только publishable |
| Database → Backups | ежедневные бэкапы (Pro) или `pg_dump` раз в неделю |
| Edge Functions | secrets только через Secrets; «Verify JWT» выключен намеренно — функции проверяют токен сами |

### Что важно знать
- **Supabase Free усыпляет проект после 7 дней без обращений** — сайт перестанет открываться, пока не нажмёшь *Restore* в панели. С живыми посетителями этого не случается; тариф Pro ($25/мес) убирает паузу совсем и даёт ежедневные бэкапы.
- Данные людей (сессии, профили) лежат только в Supabase: бэкап — **Database → Backups** (Pro) или `pg_dump` по connection string.
- Кто админ, решает таблица `admin_emails` — добавляй/удаляй строки в SQL Editor.
- Приватные сессии видит только владелец, даже админ их не видит — так устроены политики в `schema.sql`.
